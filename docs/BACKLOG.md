# 研究の「次にやること」一覧

毎日の研究の回（satou-aaaaa/shared-workflows の `routines/research-loop.md`）が、ここから1件ずつ選んで進める。
人が研究を頼んだスレッドも、始める前にここに項目を足し（または「作業中」にし）、終わったら「済み」にして結果を書く。
書き方は `tests/test_backlog.py` が確かめる。

- 見出しは `## R-<3桁の番号> <題>`。番号は使い回さない。
- `- 状態:` 次 / 作業中 / 済み / 保留 / やめた。作業中は1件まで。
- `- 優先:` 1（先にやる）〜 5。同じなら番号の若い順。
- `- 待ち:` 先に済んでいてほしい項目の番号（あれば）。
- `- 完了条件:` 何がそろえば済みか（対局数・比べる相手・記録する場所）。必ず書く。
- `- 手がかり:` 前の結果・メモ・出典。
- `- 実行:` 重い計算を Actions（`research-run.yml`）で回しているときの名前。結果はブランチ `research-results` の `runs/<名前>/`。
- `- 結果:` 済みにしたとき、PR 番号と1行の結論（効かなかったときも書く）。
- `- 保留の理由:` 保留にしたとき、何が決まれば・そろえば再開するか。

## R-001 終盤の厳密値を教師に、勝率を予測する評価関数を学ぶ
- 状態: 済み
- 優先: 1
- 実行: r-001-20261115
- 完了条件: 山札の残り3〜4枚の局面を `endgame.solve`（勝率）で解いた値を教師にして、勝率を予測する形の評価（線形かロジスティック、特徴量は今の36個）を学び、最新チャンピオンの評価と同じ探索で先後入れ替え200局以上を比べる。結果を docs/EXPERIMENTS.md に書く。
- 手がかり: 2026-11-12 の GTO 測定（PR #186）。残り4枚は1局面 中央値5.5秒なので、教師づくりは research-run.yml で回す。線形評価は検証R²≈0.4で頭打ち（2026-10-14）。局面は project-files の features2/records か、新しく自己対戦で作る。
  2026-11-15: 400局の残り0〜3枚（全局）と残り4枚（55局）の3310行を `scripts/endgame_teacher.py` で読み切って学習。検証（80局）の対数損失は チャンピオン（tanh(v/30) で勝率に読み替え）0.329 → 学習 0.111、勝ち負けの当たり 95.7% → 97.5%（`docs/results/endgame_teacher_fit.json`）。残り4枚以下だけ切り替える評価 `models/eval_eg_split.npy` と、対照 `models/eval_eg_split_ctrl.npy`（中身はチャンピオン gen1244）を標準・最強の探索で各200局（`scripts/sweeps/r001_endgame_teacher.sh`）。
- 結果: PR #220（学習）と本PR（判定）。標準200局 0.520 [0.451, 0.588]・最強200局 0.460 [0.392, 0.529]、合わせて0.49で差なし→不採用。残り3枚以下は既に読み切っていて、変えられる手が残り4枚付近だけなので効きにくい。docs/EXPERIMENTS.md「2026-11-16 終盤の厳密値を教師にした勝率型の評価」。
